# `content/` — the pipeline's working directory

This folder is the content pipeline's disk workspace (fetch cache, staged
imports, generated reports). It is **not** where questions are authored.

- **Authoring**: questions live in [`src/data/questions/*.ts`](../src/data/questions),
  written with the `q()` helper for type-safety and editor support. That
  remains the single editable source for our own `derived`/`practice`
  content.
- **`questions/official|derived|practice/`**: placeholders for raw content
  staged from an *external* source of that provenance, before it's reviewed
  and (if cleared) turned into entries in `src/data/questions/*.ts`. Empty
  today — see `CONTENT-LICENSES.md` for why nothing has been auto-imported.
- **`questions/generated/`**: build output. `scripts/build-content.ts` reads
  `src/data/questions` (our real content) plus anything reviewed out of
  `imports/*/staged`, validates + deduplicates + hashes it, and writes a
  snapshot here per category. This is the artifact described in the content
  spec's pipeline diagram; the app itself does not read from it at runtime
  (it imports the TS modules directly, for zero-latency dev/HMR).
- **`imports/<source>/staged/`**: where a local, manually-and-legally-obtained
  export from an external source (e.g. a personally-run DGT sede test
  session, or an Anki `.apkg` you have rights to use) gets dropped by an
  admin before running the matching `scripts/import-*.ts`. Everything landing
  here is tagged `needs_review` and is never auto-merged into `src/data`.
- **`signs/`**: same idea, for the traffic sign catalogue (`src/data/signs.ts`
  is the authored source; nothing here yet, since we have no license to
  redistribute DGT's official pictogram artwork — see CONTENT-LICENSES.md).
- **`sources/`**: generated by `scripts/export-sources.ts` from
  `src/data/sources.ts` (also the real source of truth) — JSON mirror used
  by `CONTENT-LICENSES.md` generation and by other tooling that would rather
  not import TypeScript.
- **`metadata/`**: build reports (`build-report.json`, `content-hashes.json`)
  written by `scripts/build-content.ts`. `.cache/` (gitignored) holds the
  fetcher's on-disk HTTP cache.

Run the whole pipeline with `npm run content:update` from the project root.
See [`docs/content-pipeline.md`](../docs/content-pipeline.md) for the full
walkthrough and [`CONTENT-LICENSES.md`](../CONTENT-LICENSES.md) for what we
can and can't reuse from each source.
